# BD-32. Refresh 재사용을 감지해도 세션 계열을 폐기하지 않는다 (당분간)

- **상태**: **Superseded by [BD-35](BD-35-refresh-reuse-family-revocation.md)** (2026-07-29) — 아래 재검토 트리거대로 [back#73](https://github.com/Team-PinLog/back/pull/73) 병합 직후 계열 폐기를 구현했다(Jira 작업). 이 문서가 기록한 "감수하는 것"은 **더 이상 유효하지 않다.**
- **날짜**: 2026-07-29
- **관련**: Jira 작업 · [BD-21](BD-21-auth-token-model.md)(토큰 모델) · [BI-18](../implements/BI-18-2026-07-28-jwt-cookie-session.md)
- **작성 시점**: 2026-07-29 — 코드 리뷰에서 지적받아 정리

## 맥락

`AuthTokenService.rotate`는 이미 소비된 `jti`로 들어온 요청에 401을 돌려준다. 재사용을 **감지는 하지만** 그 회원의 다른 Refresh 토큰은 건드리지 않는다.

토큰이 유출된 상황을 따라가 보면 문제가 드러난다.

1. 공격자가 Refresh를 탈취한다
2. 공격자가 먼저 회전 → 새 토큰 쌍을 얻는다. **공격자의 세션은 살아 있다**
3. 정상 사용자가 나중에 회전 시도 → 이미 소비된 `jti`라 401
4. 사용자는 재로그인하고, **공격자의 세션은 그대로 유지된다**

[RFC 9700](https://www.rfc-editor.org/rfc/rfc9700.html) §4.14.2가 재사용 감지 시 해당 사용자의 refresh 토큰을 **전부** 폐기하라고 하는 이유가 이 시나리오다. 우리는 그 절반(감지)만 하고 있다.

## 선택지

| 안 | 장점 | 단점 |
|---|---|---|
| (a) 지금 계열 폐기 구현 | RFC 권고를 충족한다. 유출 시 공격자 세션이 끊긴다 | 회원당 `jti` 집합을 따로 들어야 한다(Set 하나 추가). 저장 구조와 폐기 경로가 늘고, 이 PR은 이미 과대하다 |
| (b) `SCAN`으로 폐기 | 자료구조 추가가 없다 | `auth:refresh:<memberId>:*` SCAN은 키 공간에 비례한다. 운영 Redis에서 권장되지 않는다 |
| **(c) 감지만 유지, 폐기는 후속** | 이 PR의 크기를 늘리지 않는다. 감지·401은 이미 동작하고 테스트로 고정돼 있다 | **유출 시 공격자 세션이 살아남는다.** 그 사실이 문서에 없으면 아무도 모른다 |

## 결정

**(c)** — **능동적 선택.** 다만 "안 한다"가 아니라 **"지금 안 하고, 안 한다는 사실을 드러낸다"** 이다.

근거는 위험의 크기가 아니라 **PR 크기**다. 이 PR은 이미 파일 100개를 넘겼고, 계열 폐기는 저장 구조(회원당 Set)와 폐기 경로를 새로 만드는 일이라 독립 티켓의 몫이다. 위험이 작아서 미룬 것이 아니다.

재사용 감지 시 `WARN`을 남긴다. 폐기를 안 하더라도 **일어났다는 사실은 보여야** 운영에서 판단할 수 있다.

## 결과

**감수하는 것**

- **Refresh가 유출되면 공격자 세션이 최대 7일 살아남는다.** 정상 사용자가 401을 받아 재로그인해도 공격자는 끊기지 않는다. 사용자는 "로그아웃됐네" 정도로 받아들이고 유출을 눈치채지 못한다.
- 이것은 [BD-21](BD-21-auth-token-model.md)이 적어 둔 "무효화 지연"(로그아웃 후 Access 30분)과 **다른 구멍**이다. 그쪽은 시간이 지나면 닫히고, 이쪽은 공격자가 계속 회전하는 한 닫히지 않는다.

**재검토 트리거**

- **이 PR이 병합되는 즉시** 후속 티켓으로 올린다. 미루는 결정이지 포기하는 결정이 아니다.
- 회원 탈퇴(Jira 작업)를 구현할 때 — 그쪽도 `auth:refresh:<memberId>:*`를 한 번에 지워야 하므로 같은 자료구조가 필요하다. **두 작업을 같이 하는 것이 자연스럽다.**
- 재사용 감지 `WARN`이 실제로 관측되기 시작하면 우선순위를 올린다.
