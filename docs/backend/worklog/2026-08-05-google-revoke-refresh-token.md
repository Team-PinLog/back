# Google 탈퇴가 승인을 남기던 것을 refresh token 폐기로 고쳤다

- **날짜**: 2026-08-05
- **추적**: Jira 작업
- **관련**: [BD-48](../decisions/BD-48-unlink-before-withdrawal.md)(§① 정정) · [BI-41](../implements/BI-41-2026-08-05-google-revoke-refresh-token.md) · [back#190](https://github.com/Team-PinLog/back/issues/190) · [front#97](https://github.com/Team-PinLog/front/pull/97)

Google로 가입한 회원이 탈퇴해도 Google 계정의 「서드파티 앱 및 서비스」에 앱이 남았다. Kakao·Naver는 정상이었다.

## 200을 성공으로 읽은 것이 출발점이다

서버는 access token을 `/revoke`에 보내 `200`을 받고 `social account unlinked before withdrawal`을 남긴다. **그 `200`이 무엇의 성공인지 확인하지 않았다** — 토큰이 폐기된 것이지 승인이 해제된 것이 아니다.

사용자가 "구글은 안 되는 것 같다"고 했을 때 나는 **로그만 보고 "구글도 정상 동작했다"고 단정했다.** 로그에 `unlinked`·`completed`가 찍혔고 DB도 `withdrawn:3`이었기 때문이다. 그 판단 위에서 원인을 **티켓 재생**으로 지목하고 수정안까지 냈다. 사용자가 "내가 구글 계정 보고 말한 거야"라고 하고서야 뒤집혔다.

**두 번 같은 실수를 했다.** 앞선 Naver 건에서도 1차 출처를 손에 쥐고 2차 자료로 갈아탔고, 이번엔 관측 대신 로그를 근거로 삼았다. 로그는 우리가 무엇을 **호출했는지**를 말할 뿐 공급자 쪽 **상태**를 말하지 않는다.

## 원인

Kakao(`/v1/user/unlink`)·Naver(`/oauth2.0/revoke`)는 **연결 단위** API고 Google `/revoke`는 **토큰 단위**다. 승인은 refresh token 쪽에 달려 있는데, 우리 인가 요청은 `scope: openid,email`뿐이라 refresh token을 받지 않았다. 폐기 연쇄가 access → refresh 방향이라 연쇄할 대상이 없었다.

## 고친 방식

탈퇴 왕복의 **Google 인가 요청에만** `access_type=offline`·`prompt=consent`를 붙여 refresh token을 받고 그것을 폐기한다.

- **로그인 진입에는 붙이지 않는다.** 붙이면 매 로그인마다 동의 화면이 뜬다.
- **Kakao·Naver는 안 건드린다.** 연결 단위라 이미 끊기고, 남의 인가 요청에 Google 전용 파라미터를 실을 이유가 없다.
- **보관 원칙은 그대로다.** refresh token은 토큰 교환 응답으로 와서 같은 요청 안에서 `/revoke`로 나가고 사라진다. BD-48 §①이 기각한 것은 *로그인 시점에 받아 보관*하는 안이다.

대가는 탈퇴 시 동의 화면이 자동 통과 대신 실제로 뜨는 것이다. 계정 삭제 앞이라 명시적 승인이 오히려 맞다.

## 함께 드러난 것 — 아직 안 고쳤다

**탈퇴 티켓이 재사용된다.** 로그에 7초 간격으로 같은 회원의 왕복이 두 번 찍힌 적이 있고, 두 번째가 새 승인을 만들었는데 우리는 그것을 끊지 않는다(§⑤ — 마스킹 후엔 소유 확인 불가).

BD-48 §②에 *"티켓은 진입에서 일회 소비한다"*고 써 놓고 구현하지 않았다. 나중에 그 불일치를 발견했을 때 **코드가 아니라 문서를 내렸고**, 그때 든 근거(*"재생해도 그 사용자로 공급자 인증을 통과해야 한다"*)가 틀렸다 — 통과하면 새 승인이 생긴다.

그리고 (C)안(Redis 티켓 보관)을 기각한 이유를 **사용 기록에도 확대 적용한 것**이 실수다. 티켓 자체를 저장하면 Redis 재시작이 진행 중 탈퇴를 끊지만(fail-closed), 사용한 `jti`만 기록하면 잃어도 지금과 같아질 뿐이다(fail-open). 실패 방향이 정반대인데 같은 것으로 봤다.

이번 증상의 원인은 아니라 별도 티켓으로 남긴다.
