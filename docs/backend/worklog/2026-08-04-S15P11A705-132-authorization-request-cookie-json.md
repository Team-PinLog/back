# 인가 요청 쿠키를 Java 직렬화에서 JSON으로 바꿨다

- **날짜**: 2026-08-04
- **추적**: S15P11A705-132
- **관련**: [BD-49](../decisions/BD-49-authorization-request-cookie-json.md) · [BD-30](../decisions/BD-30-authorization-request-in-cookie.md)(대체된 결정) · [back#175](https://github.com/Team-PinLog/back/issues/175)

BD-30이 고른 Java 직렬화를 걷어내고 Spring Security의 공식 Jackson 모듈로 바꿨다. 형식만 바뀌고 쿠키에 담는다는 결정과 속성은 그대로다.

## 이 작업을 두고 내가 갈팡질팡했다

먼저 제안했다가, *"기각했는데 지금 하자는 근거가 뭐냐"*는 반문에 답하지 못하고 미뤘다. 나중에 다시 하자고 했다. 사용자가 그 일관성 없음을 지적하며 **공식 자료를 근거로 확정하라**고 요구했고, 그제야 조사해서 답이 나왔다.

**내가 놓쳤던 것은 하나다 — BD-30의 기각 사유가 이미 사실이 아니었다.** Spring Security 7.1.0이 `OAuth2ClientJacksonModule`을 제공한다. 그 존재를 확인하지 않은 채 "업그레이드하면 깨진다"만 들고 갔으니 설득력이 없던 게 당연하다. BD-30의 선택지 표에는 **"쿠키 + 공식 Jackson 모듈"** 행이 통째로 빠져 있었다.

교훈은 "밀어붙였어야 했다"가 아니다. **기존 결정을 뒤집으려면 그 결정의 근거가 아직 유효한지부터 확인해야 한다.** 나는 새 근거를 찾는 데만 매달렸다.

## 구현 중에 드러난 것

`attributes`의 `withdrawal_member_id`가 `Long`이라 **JSON 경로의 `PolymorphicTypeValidator`에 거부됐다.** 검증기를 넓히지 않고 값을 String으로 맞췄다 — 이번에 세우는 방어를 스스로 깎을 수는 없다.

**먼저 써 둔 생존 테스트가 이걸 잡았다.** 없었으면 로그인은 멀쩡하고 탈퇴만 조용히 깨진 채 나갔을 것이다. BD-30이 JSON을 기각하며 든 *"필드 누락이 조용한 버그가 된다"*가 형태를 바꿔(누락이 아니라 타입) 실제로 나타난 셈이다.

부수적으로, 새 검증기가 옛 필터보다 좁다는 것이 이 거부로 증명됐다. 옛 `ObjectInputFilter`는 `java.lang.**`을 통째로 열어 두었다.

## 픽스처에 실제 자격증명을 넣었다

쿠키 크기 회귀 테스트를 쓰면서 "실제 형태에 맞춘다"는 이유로 앞선 curl 스모크의 리다이렉트 URL에서 값을 복사했다. 거기에 **`.env`의 실제 Google `client_id`가 있었다.** 사용자가 *"이 해시값들 무작위 맞냐, clientId는?"* 이라고 묻지 않았으면 그대로 푸시됐다.

- 노출 범위: **미푸시 커밋 하나**. PR·이슈·docs 등 외부 표면은 0건
- amend만으로는 부족했다 — 옛 커밋 객체가 reflog에 살아 `git show`로 읽혔다. `reflog expire` + `gc --prune=now`로 지웠다
- 필요한 것은 내용이 아니라 **길이**였다. 길이만 맞춘 합성 값으로 교체

함께 조인 것: `.gitignore`에 `*.pem`·`*.key`·`*.p12`·`*.jks`(규칙 자체가 없었다), `.env`를 소유자·SYSTEM 전용 ACL로. 다만 **권한으로는 이 사고를 못 막는다** — 에이전트 셸이 소유자 계정으로 돈다. 실제 방지책은 커밋 직전 검사라서 `.env` 값과 스테이징 내용을 대조하는 pre-commit 훅을 걸고 실제 유출을 재현해 차단을 확인했다.
