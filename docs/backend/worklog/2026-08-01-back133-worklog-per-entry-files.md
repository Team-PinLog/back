# 작업 로그와 기록 목록을 항목별 파일로 분리했다

- **날짜**: 2026-08-01
- **추적**: back#133
- **관련**: [BD-45](../decisions/BD-45-worklog-per-entry-files.md) · [#152](https://github.com/Team-PinLog/back/pull/152)

열린 PR이 둘 이상이면 반드시 충돌하던 공유 append 파일을 없앴다. 이 파일이 새 구조의 첫 항목이다.

## 왜 했나

`WORKLOG.md`는 모든 작업이 표 끝에 한 행을 더하는 구조라, 브랜치 둘이 같은 지점에서 부딪혔다. `.gitattributes`의 `merge=union`은 **로컬 머지 드라이버라 GitHub 서버 병합에 걸리지 않아**, `gh pr update-branch`가 두 번째 PR부터 항상 실패했다. `dev`가 `strict: true`라 갱신마다 CI 3분이 다시 들었고, 2026-07-31에 PR 4건을 묶으며 CI 7회와 수동 개입 3회를 썼다.

## 이슈보다 범위가 넓었다

이슈는 `WORKLOG.md` 하나를 봤지만 같은 성질의 파일이 **다섯 개**였다. union이 걸린 건 하나뿐이라 나머지 넷은 로컬 병합에서조차 union을 못 탔다.

`spec/README.md`는 폴더가 비어 있어 아직 터지지 않았을 뿐 "이 표에 등록합니다"라고 지시하고 있었다 — 최종 리뷰에서 잡았다. 터지기 전에 잡은 유일한 경우다.

## 결정을 굳힌 근거

인덱스 표가 **이미 틀려 있었다.** `implements`는 `BI-22`를 빠뜨렸고, `troubleshooting`은 `BT-02`를 미해결로 적어뒀는데 문서는 이미 해결이었다. 뒤쪽이 더 나쁘다 — 빠뜨린 게 아니라 해결된 문제를 열린 것처럼 보고했다.

기록 문서 84개 전부가 H1에 번호·요약을, 헤더에 상태를 원본으로 갖고 있었으니 표는 손으로 뜬 사본이었다. `decisions/README.md`가 스스로 "같은 결정에 원본이 둘이 되면 반드시 어긋난다"고 적어둔 원칙을 자기 목록 표가 어기고 있었다.

## 감수한 것

파일 하나를 열어 전부 훑는 방식이 없어졌다. AI 파트가 이슈에서 지적한 실재하는 손실이다. 대신 파일명이 시간순 목록을 주고 각 폴더 `README.md`가 훑는 명령을 제시한다 — 문서를 직접 읽으므로 손으로 관리하던 표보다 정확하다.

이슈 제안과 한 가지 다르게 판단했다. `merge=union`을 "얼린 파일용으로 남긴다(무해)"고 했지만 **지웠다.** 멈춘 파일에는 발동할 일이 없고, 남겨두면 주석이 현재형으로 틀린 설명을 계속하며 "union이 있으니 공유 파일을 하나 더 만들어도 되겠다"고 읽을 여지를 남긴다.

## 검증

대조군을 먼저 돌렸다 — 그쪽이 실패하지 않으면 실험군의 성공이 아무것도 증명하지 않는다. `dev`를 건드리지 않도록 던져버릴 base 브랜치 위에서 했고 흔적은 전부 지웠다.

| | `gh pr update-branch` | mergeable |
|---|---|---|
| 대조군 (옛 구조, 같은 파일에 각각 추가) | `X Cannot update PR branch due to conflicts` | `CONFLICTING` |
| 실험군 (새 구조, 겹치는 파일 0건) | `✓ PR branch updated` | `MERGEABLE` / `CLEAN` |

갱신된 브랜치에 양쪽 파일이 모두 남은 것도 확인했다.
