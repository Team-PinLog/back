# 작업 로그 (Worklog)

작업 하나가 파일 하나입니다. 브랜치가 몇 개든 파일이 겹치지 않으므로 병합 충돌이 나지 않습니다.

**인덱스·목록 파일을 두지 않습니다.** 목록 파일을 만드는 순간 모든 브랜치가 같은 파일을 고치게 되어, 이 구조가 없애려던 충돌이 그대로 되살아납니다. 시간순은 파일명이 줍니다.

작업 로그 항목은 기록입니다. 삭제하지 않습니다 — 상태 필드가 없어 갱신할 대상도 없고, 바로잡을 일이 생기면 그 사실을 적은 새 항목을 추가합니다.

## 파일명

```
YYYY-MM-DD-<추적키>-<슬러그>.md
```

`YYYY-MM-DD`는 **작업을 마친 날**입니다. 파일명과 아래 `- **날짜**:` 값을 같은 날로 맞춥니다.

| 상황 | 예 |
|---|---|
| Jira 티켓이 있을 때 | `2026-07-31-S15P11A705-238-single-stage-image.md` |
| GitHub 이슈만 있을 때 | `2026-07-28-back58-published-at-invariant.md` |
| 추적 키가 없을 때 | `2026-07-31-configuration-drift.md` |

- 추적 키가 없으면 **슬롯을 통째로 생략합니다.** 없는 키를 지어내거나 `none` 같은 자리채움을 넣지 않습니다.
- GitHub 이슈는 파일명에서 `#`을 뺀 `back58`처럼 씁니다(파일명에 못 쓰는 문자라서입니다). 찾을 때도 `back#58`이 아니라 `back58`로 찾습니다.
- **슬러그는 그 작업을 특정할 만큼 구체적으로 씁니다.** 같은 날 · 추적 키 없음 · 같은 슬러그인 파일을 두 브랜치가 각각 만들면 그때는 다시 겹칩니다. 추적 키가 있으면 그럴 가능성이 줄어들 뿐, 결국 구분은 슬러그가 집니다.

## 형식

```markdown
# 한 줄 요약

- **날짜**: 2026-08-01
- **추적**: S15P11A705-238
- **관련**: [BD-45](../decisions/BD-45-worklog-per-entry-files.md) · `abc1234` · [back#133](https://github.com/Team-PinLog/back/issues/133)

본문 — 무엇을 왜 했는지, 그때 내린 판단.
```

커밋 메시지를 옮겨 적는 자리가 아닙니다. **의도와 결정**을 씁니다. 추적 키가 없으면 `- **추적**:` 줄을 뺍니다.

## 훑어보기

```bash
find docs/backend/worklog -maxdepth 1 -name '20*.md' | sort                             # 시간순 전체 (README.md 제외)
find docs/backend/worklog -maxdepth 1 -name '20*.md' -exec grep -l S15P11A705-238 {} +  # 티켓 하나
find docs/backend/worklog -maxdepth 1 -name '20*.md' -exec grep -h '^# ' {} +           # 요약만
```
